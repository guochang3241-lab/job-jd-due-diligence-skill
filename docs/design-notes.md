# 设计与迭代

## 问题定义

求职者看 JD 时，常能得到公司简介、职责翻译和面试反问，却仍难判断岗位在具体业务里创造什么价值。这个 Skill 的交付对象是求职者，核心任务是把公开事实连接到业务机制和决策，再检查目标与条件是否匹配。

## 版本变化

早期 `job-jd-due-diligence` 版重点是岗位风险：业务需求、数据基础、权责资源、交付预期等七维评估。v1 增加三个前置层次：公司竞争差异与变化、公司特定业务洞察、岗位决策场景。这样，最终的风险判断有业务内容作依据，面试问题也能检验实际决策价值。

这是设计意图，不代表已有用户效果数据。旧版仍保存在作者本地工作区，不作为本仓库的运行入口。

## 关键取舍

1. **先研究业务，再评估岗位。** JD 是研究入口；公司材料可能揭示 JD 没有写出的经营取舍。
2. **允许有依据的业务推导。** 内部资料缺失时仍可解释公开事实可能影响什么决策，同时标明前提和反证。
3. **证据和风险分开。** “没有查到团队预算”是未知；明确要求短期交付且必要输入无法取得，才是风险依据。
4. **输出面向行动。** 每个主要场景要说清决策人、动作、输入、交付物和效果观察，而不只列指标或工具。

## 本次公开整理的修正

虚构示例原先在“首期是否必须完成毛利分析”尚不明确时，把成本协作缺口直接评为高风险。公开版将结论改为待确认，并写明两种情况各自如何改变判断。这与 Skill 的证据规则一致。

## 仍需验证

当前缺少同条件模型对照和真实求职者使用反馈。后续应记录原始输出、来源错误、泛化分析、问题可执行性，以及面试新信息是否能正确更新结论。不要用输出篇幅或引用数量替代这些指标。
