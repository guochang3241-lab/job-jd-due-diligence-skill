# 岗位调研助手｜从公司业务看懂一个岗位

**直接点下面的案例即可阅读，无需安装或运行任何工具。**

我设计了一个可重复使用的岗位调研方法：先理解公司如何做生意，再分析岗位能帮助谁作出什么决策，最后核对目标与资源是否匹配。它把“读 JD”推进到“理解业务、形成判断、准备有价值的面试问题”。

## 从这里开始

- **先看成果（约 3 分钟）**：[腾讯云经营分析经理：真实公开资料案例](examples/tencent-cloud-case.md)。看一个岗位如何从公司资料走到业务洞察、候选工作场景和待验证问题。
- **再看我的思路（约 2 分钟）**：[设计与迭代说明](docs/design-notes.md)。看我为什么这样设计，以及如何修正一次判断过度的问题。
- **想看完整规则**：[Skill 主文件](SKILL.md)。这是让 AI 按上述方法工作的说明书，前两项已经足够了解作品。

例如，公开资料提到云服务增长，岗位 JD 要求经营分析。作品没有直接把“增长”当成岗位机会，而是继续追问：增长来自新客户、续约、价格还是用量？不同来源的收入，对资源投入和后续决策意味着什么？[完整案例](examples/tencent-cloud-case.md)同时标出哪些只是待验证的推断。

## 这个项目展示什么能力

- **业务拆解**：把公司事实和商业模式连接到具体经营决策，而不只复述公司介绍。
- **分析设计**：明确决策者、所需信息、可交付成果和后续行动。
- **判断边界**：区分已核实事实、合理推断和内部未知条件，避免把猜测写成结论。
- **迭代意识**：用案例检查常见误判，并在新信息出现时更新判断。

“Skill”在这里指一份可复用的 AI 工作说明书，供求职者评估岗位。公开案例经过人工复核；目前尚无同条件模型对照结果，详情见[验证记录](docs/validation.md)。

## 文件与使用方式

- [SKILL.md](SKILL.md) 定义从 JD 拆解、公司研究、业务洞察、决策场景到岗位条件评估的主流程。
- [研究与证据指南](references/research-and-evidence.md) 规定来源、主体、时间和口径的边界；公开宣传不能直接证明团队条件。
- [业务场景框架](references/business-model-probes.md) 提供按实际行业选用的机制问题，避免把行业常识套成公司事实。
- [评估规则](references/assessment-and-questions.md) 把“待确认”和“高风险”分开，不用总分掩盖决定性矛盾。
- [虚构完整示例](references/worked-example.md) 演示报告尺度；[验证案例](references/validation-cases.md) 是测试输入与核验标准，不等于已通过的测试。
- [对照协议](docs/comparison.md) 记录未来如何比较普通提问与启用 Skill 的效果；尚未完成独立运行。

如需自己运行，将本目录复制到 Codex 的 skills 目录，使 `SKILL.md` 位于 `skills/job-jd-due-diligence-v1/SKILL.md`，然后在新对话中输入：

```text
使用 $job-jd-due-diligence-v1，分析以下机会。
公司：……
岗位：……
JD 或招聘链接：……
我最想判断：……
```

提供完整 JD、目标业务单元、地点和发布时间会提高判断质量。研究当前公司需要可用的联网检索工具；离线使用时，输入已有资料即可。

## 适用范围

侧重经营分析、数据、AI、产品及复合型岗位。公开资料能帮助理解业务和提出问题，通常无法证实内部数据权限、预算、协作和考核安排。分析结论仅支持是否继续了解岗位，不替代面试核实。

本项目以 MIT 许可证开放。外部公司与岗位材料仍归各自权利人所有，仓库只保留必要的短摘和来源链接。
