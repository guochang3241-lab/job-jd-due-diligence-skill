# 岗位调研：从公司业务到岗位决策的 Skill

给正在评估岗位的求职者使用，预计节省 80% 调研时间。

输入公司、岗位和 JD，Skill 会先研究公司的交易与经营方式，再把资料转成岗位相关的决策场景，最后判断职责、数据、权限和资源能否支撑交付，并提出值得在面试中验证的问题。

它解决的典型问题是：公司资料和 JD 都能搜到，却很难回答“这个岗位究竟帮谁做什么决定、所需条件是否具备”。

## 看一个例子

公开 JD 要求经营分析、业财指标和经营复盘。以[腾讯云经营分析经理](examples/tencent-cloud-case.md)为例，腾讯的公开披露能支持“云服务需求增长”这一背景，但不能证明目标团队已有可用的客户级成本数据。由此可以提出一个具体分析场景：区分客户收入增长来自新增、续约还是用量变化，并与算力、交付及支持成本一起看客户贡献。这个场景是候选切入点，是否属于该岗位的首期任务仍需面试确认。

## 运行方式

将本目录复制到 Codex 的 skills 目录，使 `SKILL.md` 位于 `skills/job-jd-due-diligence-v1/SKILL.md`。在新对话中调用：

```text
使用 $job-jd-due-diligence-v1，分析以下机会。
公司：……
岗位：……
JD 或招聘链接：……
我最想判断：……
```

提供完整 JD、目标业务单元、地点和发布时间会提高判断质量；缺少材料时，Skill 会标明无法确认的部分。研究当前公司需要可用的联网检索工具。离线使用时，输入已有资料即可，但不能声称完成了实时查证。

## 设计要点

- [SKILL.md](SKILL.md) 定义从 JD 拆解、公司研究、业务洞察、决策场景到岗位条件评估的主流程。
- [研究与证据指南](references/research-and-evidence.md) 规定来源、主体、时间和口径的边界；公开宣传不能直接证明团队条件。
- [业务场景框架](references/business-model-probes.md) 提供按实际行业选用的机制问题，避免把行业常识套成公司事实。
- [评估规则](references/assessment-and-questions.md) 把“待确认”和“高风险”分开，不用总分掩盖决定性矛盾。
- [虚构完整示例](references/worked-example.md) 演示报告尺度；[验证案例](references/validation-cases.md) 是测试输入与核验标准，不等于已通过的测试。

## 适用范围

侧重经营分析、数据、AI、产品及复合型岗位。公开资料能帮助理解业务和提出问题，通常无法证实内部数据权限、预算、协作和考核安排。分析结论仅支持是否继续了解岗位，不替代面试核实。
