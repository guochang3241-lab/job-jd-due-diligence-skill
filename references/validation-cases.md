# 维护验证案例

用途：修改 Skill 后检查业务洞察深度、决策场景及证据边界。以下材料全部虚构。执行时明确这是离线材料测试，不联网补全虚构公司；不将材料当成真实岗位调查。

把每个案例的“输入”作为单独请求，按 Skill 给出简版分析。再用后面的核验要点检查结果。不要把核验要点当作新增事实；同一输入可以有不同措辞，重点是推断边界及行动建议。

## 案例输入

### A：局部数据治理

甲公司经营分析岗 JD 写“负责数据治理与指标统一”。用户提供的负责人记录称：已有覆盖全店的数据仓库，这次只统一退货归属日期；财务已指定口径负责人，IT 有排期，首月交付定义及核对结果。问是否说明公司数据基础很差。

### B：有支持条件的从 0 到 1

乙公司新业务分析岗 JD 写“从 0 到 1”。负责人记录称：使用成熟的集团平台，两个数据工程师已被安排支持，首期只做一个区域的周报试点；业务经理确认使用并验收。用户问是否属于一个人从头搭所有系统。

### C：明确的目标与资源冲突

丙集团知名度很高。负责人和 IT 的面试记录均明确：该岗位必须一个月上线覆盖全国的实时监控；核心系统半年内无法提供接口，也不允许人工导出；不调整期限或范围，没有其他输入渠道。用户问能否凭集团资源相信能够做成。

### D：公开信息稀少

丁公司仅有一份“经营分析专员”JD，写销售报表和经营建议，无明确业务单元、输入来源及验收方式。用户说明暂不联网，只要求基于材料判断；没有其他负面证据。

### E：规模大但不必使用 AI

戊公司要每天按固定阈值筛查 5,000 条库存记录。输入字段稳定，已有可导出报表，异常由业务人员复核，没有非结构化解释任务。用户问是否必须上大模型，但没有提供预算和现有技术栈。

### F：集团宣传与团队条件

己集团官网宣称“完成数字化平台建设”。目标岗位在一家子公司，HR 只说“应该可以用”，没有确认权限、数据覆盖或接口。用户问能否把数据基础评为较好。

### G：招聘动因的因果跳跃

庚公司三个月前宣布新开门店，本月发布经营分析岗。材料没有写新增或替补，没有团队信息。用户问是不是因为扩张所以新增该岗位。

### H：验证后更新结论

延续完整示例。新增用户转述：负责人、财务和 IT 已共同明确首期只做销售异常，现有销售导出可用；财务负责人下季度补成本映射，不纳入首期考核；区域经理接受周度复盘。用户问是否仍应保留原来的高风险判断。

## 核验要点

除 A 至 H 的证据边界案例外，使用以下 I 至 L 检查业务研究是否只是通用摘要。

### I：直营与加盟的经营差异

输入：辛公司同时经营直营和买断供货的加盟渠道；提供材料明确总部对加盟商按供货结算，加盟商自行承担终端库存，没有按终端销售额抽佣。JD 要求分析全渠道经营及补货，现有数据有总部出货、回款和直营零售流水，没有加盟终端销量。用户希望理解公司业务及岗位价值。

核验：应解释总部供货与终端需求的区别、两种渠道的核算及可见性差异，提出有条件的渠道分析场景；不能假定加盟抽佣、终端数据存在或渠道已压货。只写“统一口径、搭建看板”不通过。

### J：订阅增长中的不同解释

输入：壬公司订阅收入同比增长 20%，公司材料同时披露新增企业客户增加、存量客户续费率由 90% 降至 84%；续费率为同口径客户数口径，未给出金额留存。JD 是客户经营分析，协助销售和客户成功团队配置资源。用户希望理解业务重点。

核验：区分新增和存量、客户数和金额，说明按客户批次或规模拆解的价值，提出续费跟进或资源配置场景及所需输入。不能仅凭客户续费率下降计算流失收入，也不能直接断言产品质量差或认定岗位无资源。

### K：业务事实丰富、内部条件缺失

输入：癸公司公开产品资料说明其承接定制设备项目；提供的合同样本约定预付款、交付款和验收款，售后服务另签年度合同。JD 要求项目经营分析。没有财务数值、系统或团队资料。用户要求基于这些材料分析，不联网。

核验：应说明项目里程碑、收入与回款的区别以及设备和售后两类业务，提出项目成本、验收或回款分析场景，同时保留岗位资源判断。不能整篇都写“内部情况待确认”，也不能假定公司已出现逾期或资金困难。

### L：缺少差异证据时的收敛

输入：子公司官网只有“行业领先、客户至上、智能赋能”，一份 JD 写“分析业务并提出经营建议”，没有产品、客户、竞品或可比财务材料。用户仅允许使用这些材料。

核验：说明不能形成公司特定竞争判断，最多提供明确标注的研究框架与最少缺口。不能强行凑两至四条洞察、虚构同行、把宣传当优势，或把泛化指标清单当研究完成。

| 案例 | 必须守住的判断边界 |
|---|---|
| A | 不因“治理”推断整体基础差；区分局部任务与体系缺失，支持条件归因为面试表述 |
| B | 不因“从 0 到 1”直接判高风险；识别新业务应用与全套基础建设的区别 |
| C | 识别决定性矛盾，支持“目标与资源明显不匹配”；不让品牌或泛泛成长空间抵消它 |
| D | 支持“信息不足，暂不下结论”；未知不等于风险事实，不虚构检索结果或内部状况 |
| E | 规则、BI 或脚本是可考虑方案；规模本身不证明需要 AI，也不凭空给出精确 ROI 或实施周期 |
| F | 只能确认集团有该宣传，不能直接确认子公司条件；相关维度待确认 |
| G | 扩张是可能解释，不能确认因果；新增或替补等区别应保留为验证问题 |
| H | 随新材料更新受影响维度，可以转为条件化的“值得继续了解”；保留口头材料属性，不把旧风险永久化 |

## 结果记录

记录案例编号、实际结论、支持证据、业务解释、决策场景、越界推断、遗漏的决定性问题及所需修正。下列属于实质失败：把不存在的材料当事实、把未知直接当高风险、把宣传当内部条件、忽略明确矛盾、拒绝根据新证据更新；对有材料的案例只复述概况、只列指标、只讨论风险而不解释业务，也属于失败。

业务洞察检查三点：是否用了该公司的特定材料解释机制；是否说清谁决定什么及岗位如何帮助；是否区分事实、推断和可验证建议。用“更长”“更多行业术语”或固定洞察数量代替这三点，不算通过。

不因措辞或小节顺序不同判失败。测试案例只能验证覆盖到的行为，不证明真实调研能力或所有行业适用性。保存运行记录时与本案例说明区分；未运行时仅称为待执行的验证材料。
